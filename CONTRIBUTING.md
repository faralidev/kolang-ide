# Contributing to Kolang IDE

Thanks for your interest in contributing! 🎉 Kolang IDE is a small Electron +
CodeMirror 6 editor for the [Kolang](https://github.com/faralidev/kolang)
Persian programming language, and contributions of all sizes are welcome.

## Code of Conduct

By participating you agree to uphold our [Code of Conduct](./CODE_OF_CONDUCT.md).
Please be kind and respectful.

## Ways to contribute

- 🐛 **Report bugs** — open an issue with the bug template
- 💡 **Suggest features** — open an issue with the feature template
- 📝 **Improve docs** — README, screenshots, translations
- 🔧 **Submit code** — fix a bug or implement a feature
- 🌐 **Translate** — the UI and docs are bilingual (Persian/English); more
  translations are welcome

## Getting set up

You need:

- **Node.js ≥ 18** (Node 20+ recommended)
- **npm** (ships with Node)
- The **`kolang` interpreter** on your `PATH` for actually running code in the
  editor (only needed if you want to test the Run button; the editor itself
  works without it). See the [Kolang project](https://github.com/faralidev/kolang)
  for how to build/install it.

```bash
git clone https://github.com/faralidev/kolang-ide.git
cd kolang-ide
npm install
npm run dev   # builds the CodeMirror bundle and launches Electron with DevTools
```

If `kolang` / `kolang-linter` aren't on your `PATH`, you can point the editor
at absolute paths with environment variables:

```bash
KOLANG_BIN=/path/to/kolang KOLANG_LINTER=/path/to/kolang-linter npm run dev
```

You can also set the interpreter path from inside the app via **Settings**.

## Project layout

```
main.js              Electron main process — IPC, runs the kolang binary
preload.js           Secure bridge between renderer and main
index.html           UI (Catppuccin Mocha dark theme)
renderer.js          Renderer logic
kolang-language.js   CodeMirror 6 language package (syntax, fold, indent)
bundle.js            Bundled CodeMirror 6 (generated by `npm run build` — gitignored)
build.js             esbuild script that produces bundle.js
native/              Platform-specific kolang binaries (gitignored) for packaging
build/               Packaging assets (icon, entitlements)
.github/workflows/   CI / release workflow
```

## Workflow

1. **Pick or open an issue.** For non-trivial changes, comment first so we
   don't duplicate work.
2. **Fork & branch.** Create a branch off `main`:
   `git checkout -b fix/my-bugfix`.
3. **Make your changes.** Keep commits focused; write clear commit messages
   (see below).
4. **Test manually.** `npm run dev` → exercise the change in the UI. If you
   add something testable, add a check.
5. **Open a Pull Request.** Fill in the PR template and link the issue.

## Commit messages

We follow a light version of [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add line-number gutter toggle
fix: stop run button from staying disabled after kill
docs: clarify macOS build steps
chore: bump electron to 33.4.12
```

Keep the subject line ≤ 72 chars, imperative mood ("add", not "added").

## Building packages locally

Packaging (the `.dmg` / `.exe`) is usually done by CI, but you can do it
locally — see the [Packaging section of the README](./README.md#packaging).

## Notes

- The project intentionally stays on **Electron 33** (current stable is
  higher, but a major bump is risky). If you want to upgrade, do it in a
  dedicated PR with full manual testing.
- The CodeMirror bundle (`bundle.js`) is **generated** — don't edit it by
  hand. Edit `kolang-language.js` / `renderer.js` and re-run `npm run build`.
- `bundle.js` and `bundle.js.map` are gitignored but are listed in
  `build.files` so they ship in the packaged app — make sure to run
  `npm run build` before `npm run dist`.
